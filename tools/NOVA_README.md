# tools/nova.py — архиватор с проверкой целостности

Сжимает файлы и папки, проверяет их по sha256, умеет восстанавливать испорченный файл из `.bak` и шифровать файлы паролем.
Только стандартная библиотека Python 3.10+. Шифрование требует `cryptography` (без неё команды шифрования выдадут понятную ошибку).

Для игровых ассетов не нужен: APK уже сжат, PNG и OGG сжаты сами, а ключ шифрования пришлось бы вшивать в приложение. Полезен для бэкапов больших наборов файлов вне git.

## Команды (из корня репозитория)

```bash
python3 tools/nova.py pack <файл> [--backup]      # → <файл>.nova
python3 tools/nova.py unpack <файл.nova>          # → restored_<имя>
python3 tools/nova.py packdir <папка> [--backup]  # → <папка>.novadir
python3 tools/nova.py unpackdir <архив.novadir> [--only путь1,путь2]   # → <архив>_extracted
python3 tools/nova.py test <архив>                # проверка sha256, JSON-отчёт
python3 tools/nova.py repair <архив>              # ремонт из .bak, JSON-отчёт
python3 tools/nova.py bench <файл_или_папка>      # сравнение store / bz2 / lzma
python3 tools/nova.py encrypt <файл> <пароль>     # → <файл>.enc
python3 tools/nova.py decrypt <файл.enc> <пароль> # → <файл>
```

## Поведение
- Алгоритм выбирается по энтропии и сигнатуре: уже сжатые файлы (PNG, JPEG, ZIP и др.) хранятся как есть.
- Перед записью сжатый вариант распаковывается обратно и сверяется с sha256. Если не сходится, пробуется другой алгоритм.
- Папки: сохраняются структура, симлинки, жёсткие ссылки, права доступа.
- `--backup` копирует исходники в `.bak` рядом с архивом. Без `.bak` ремонт невозможен.
- `unpackdir` не перезаписывает существующую папку назначения.
- Пути из архива очищаются от `..`, поэтому распаковка не выходит за папку назначения.

## Ограничения
- Шифрование читает файл целиком в память, для больших файлов не подходит.
- Ремонт тоже читает блок целиком в память.
- Нет ECC: повреждённый файл без `.bak` не восстанавливается.
- Старый формат `.nova` без поля TYPE не читается.

## Статус проверки
Тесты: `tools/` не содержит тестов, они лежат отдельно. Прогнаны на Python 3.11, 3.12 и 3.13 (10 тестов: файлы, папки со ссылками и юникодом, `--only`, порча с ремонтом, шифрование, бенчмарк, повторная распаковка). На Python 3.12 и 3.13 все тесты проходят, пять запусков подряд без сбоев. На 3.11 в этом окружении `cryptography` не загружается, шифрование пропускается, остальное проходит.
